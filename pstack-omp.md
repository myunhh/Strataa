## Loading and precedence

Native skills are `skills/<name>/SKILL.md`; native delegates are `agents/poteto-agent.md` and `agents/comment-sicko.md`. Resolve the actual installed entrypoint's filesystem path (including symlinks), not the working directory. A skill's bundle root is two directories above its containing directory; an agent's bundle root is one directory above its containing directory. Resolve `<bundle-root>/pstack-omp.md` to an absolute path and read it first, then read the matching original under `<bundle-root>/vendor/pstack/` by absolute path. Do not infer a bundle from `cwd`, search `~/.cursor`, or choose a newer plugin. If resolution or a required read fails, report that dependency; do not execute a partial playbook.

This adapter is the explicit higher-priority OMP translation of the imported instructions. System/developer instructions, host tool contracts, user requests, permission boundaries, and existing configured models take precedence over this adapter and every upstream file. Treat upstream frontmatter, model names, command examples, blanket autonomy, deletion rhetoric, and platform defaults as source documentation, not host configuration or authorization. Read the original skill in full, follow its substantive task goals and applicable references, and apply these translations throughout, including nested playbooks. Resolve all original relative links from their original file inside `vendor/pstack`, never from a native wrapper. Keep vendor files unchanged; use native entrypoints for linked skills. Do not claim imported source is a working Cursor service.

## Proportionate use in coding and research

Use pstack to reduce work, not to create a checklist. This section overrides upstream blanket requirements to run a whole mode, panel, repeated review, or publication playbook whenever a supporting skill is used.

- Explore freely. Generate hypotheses, rough designs, analogies and tentative interpretations without requiring a citation or reviewer for each thought. Distinguish a proposal from an observed result when reporting it; do not turn that distinction into constant approval prompts.
- Apply the smallest useful skill. Routine edits, explanations and prose cleanup can finish inline. `unslop` removes repetition, filler and unsupported rhetorical emphasis without automatically starting a review. Ordinary wording edits do not require re-review. Optional helpers or services that are unavailable can be skipped with a brief limitation; an explicitly requested or necessary capability must still be reported as unmet.
- Check changes that alter meaning: a number, comparison condition, causal claim, strength of conclusion, or scope of a result. Inspect the relevant source or run the narrow applicable check rather than restarting the entire research review. Preserve meaningful uncertainty and negative findings without freezing every sentence or requiring identical wording.
- Scale execution checks to the changed behavior. Preserve explicit user review requests, selected ARIS verdict-bearing workflows, cost/resource limits, and authorization for irreversible or external actions. Do not invent extra gates, but do not claim a required check passed when it did not.
- ARIS owns research procedure, role boundaries and final claim decisions. Brain and bounded Workers may use relevant pstack skills for design, implementation and writing. This support does not turn Worker into a researcher/reviewer or feed the author's editing agenda into the independent Reviewer. Only change an existing workflow when the user's scope permits it.

## Tools and orchestration

- Map Cursor `Read`, `Grep`, `Glob`, `Bash`, `Write`, and `Edit` to the actual OMP `read`, `grep`, `glob`, `bash`, `write`, and `edit` contracts. Read a tool's required documentation before first use. Use `edit` for existing files and `write` for new files. Host rules on user-reported failures, permitted verification, edits, commits, and shared worktrees always win: never reproduce a user-reported error merely to confirm it, or run tests/builds/linters/formatters when the assignment forbids them. Report checks not run honestly.
- Map `AskQuestion`/`AskUserQuestion` to native `ask` only for decisions the user must make; map `TodoWrite` to native `todo`; map `Skill` and slash references to reading the corresponding native entrypoint and pinned original. These are tool translations, not permission to skip a mandatory gate. Use native `eval` browser only after reading its documentation when actual UI proof is required.
- Cursor `Task`/`task` means the available OMP `task` tool, not a shell command or a Cursor API. Its request has `i`, shared `context`, and `tasks: [{task, solutionSpace, agent, ...}]`; `agent` belongs on each `tasks[]` item, never at top level. Follow the live schema and available registered agents. Do not pass Cursor-only fields such as `subagent_type`, `run_in_background`, `is_background`, `environment: cloud`, `readonly`, or Cursor model/effort flags. Enforce read-only or write scope in the task contract and use the matching supported agent. Cloud VMs and automatic sandbox isolation are not implied.
- The parent owns plan, task decomposition, integration, permission decisions, review synthesis, and final verification. Delegates perform only their assigned slice, edit only named paths, and do not recursively fan out or invoke review/orchestration unless the host assignment expressly permits it. Poteto delegates receive this adapter's absolute path, their pinned agent original's absolute path, and the absolute pinned `vendor/pstack/skills/poteto-mode/SKILL.md` path from their parent.
- Upstream instructions to always spawn, run N lanes, use three reviewers, launch a swarm, create a watcher, resume, or keep polling are conditional on host delegation policy, actual independent work, available capabilities, and the user's scope/budget. No unconditional subagents. Do the work inline where the host requires it; if a required independent panel cannot be provided, preserve the task objective but mark that gate unavailable, not passed. Use the host's supported wait/message lifecycle, not invented Cursor resume handles or polling services.
- Use only existing configured and authorized host models. User/agent model choices and reasoning settings remain untouched. Upstream role defaults, family aliases, effort suffixes, `auto`, and `inherit-parent` are not portable model IDs. Omit optional `model` to retain an existing agent configuration where permitted; never silently replace an explicitly requested unavailable model, retry on a family default, or modify global settings. Report an unavailable required model/capability. A separate context on the same model is same-model review, not independent-model, cross-family, or cross-vendor evidence; do not infer model identity or diversity.
